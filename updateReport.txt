## Milestone 8: Installer, DB guard, built-in server router, routing fix

### Added
- `public/install.php` — web installer: creates the `school_erp` database + schema + seed
  data using configured DB credentials; shows the default admin login on success.
- `database/install.php` — CLI installer (`php database/install.php`).
- `app/Schema.php` — `installed()` helper (checks `users` table exists).
- DB guard in `public/index.php`: non-login/install/asset requests redirect to `install.php`
  when the schema is missing, instead of crashing.
- `public/_router.php` — router file for `php -S` so static assets are served directly while
  everything else goes through the front controller.
- `public/.htaccess` — Apache rewrite config (docroot = `public/`).

### Fixed (important)
- **Router bug**: route patterns lacked an optional leading slash, so `GET /login` (normalized
  to `/login`) never matched the stored pattern `login` → all routes returned 404. Now the
  regex allows an optional leading slash: `#^/?<pattern>/?$#`. Verified live: login page + CSS
  render (HTTP 200).

### How to run
```
# built-in dev server
php -S 127.0.0.1:8000 -t public public/_router.php
```
Then visit `http://127.0.0.1:8000/`, it will redirect to the installer (`/install.php`), click
"Install Database", then sign in with `admin` / `admin123`.

### DB status (environment blocker)
- The running MySQL on port 3306 is the **MySQL80 Windows service** (not the XAMPP one). It
  rejects `root` with an empty password (a root password is set), and this shell is **not
  elevated**, so the service cannot be stopped/reset without admin rights. The app is
  configured for `root/empty` per your choice. To provision the DB you have two options:
  1. Provide the real MySQL root password → put it in `config/local.php` and run
     `php database/install.php`.
  2. Reset root to empty (as admin; PowerShell as **Administrator**):
     ```
     Stop-Service MySQL80
     # start mysqld with skip-grant-tables, then:
     # ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY '';
     Start-Service MySQL80
     ```
   Then run the installer. Everything else already runs (verified login page + asset serving).

## Milestone 10: Fix "Call to undefined function mysqli_report()" (WinGet PHP on PATH)

### Root cause
- The `php` on PATH is the **WinGet PHP 8.4** (`C:\Users\BitDev\...\WinGet\Packages\PHP.PHP.8.4...`)
  which is compiled **without the mysqli extension**. When a dev server was started with that
  binary, `public/install.php` (and login) crashed with
  `Call to undefined function mysqli_report()`.
- The **XAMPP PHP 8.2** (`C:\xampp\php\php.exe`) has `mysqli` + `pdo_mysql` enabled in
  `C:\xampp\php\php.ini`.

### Fix
- Always run the dev server with the XAMPP PHP binary:
  ```
  C:\xampp\php\php.exe -S 127.0.0.1:8000 -t public public\_router.php
  ```
- Verified: `install.php` returns 200 (no fatal), login page 200. Recorded in AGENTS.md so
  future sessions use the correct PHP.

## Milestone 11: Properly fix mysqli-missing fatal (defensive code, not just docs)

Forcing people to "use the XAMPP PHP" only masks the problem. The app now handles the
missing-extension case gracefully so it never crashes with
`Call to undefined function mysqli_report()`.

### Code changes
- `app/helpers.php` — new `check_mysqli(bool $cli=false)` helper. Renders a clean, styled
  error page (HTTP 500) explaining mysqli is missing and showing the exact dev-server command,
  plus the offending PHP binary/version. In CLI mode (`$cli=true`) prints the message to STDERR
  and exits non-zero.
- `public/index.php` — calls `check_mysqli()` after boot, so the whole app fails fast with a
  readable message instead of a fatal.
- `public/install.php` — requires `helpers.php` and calls `check_mysqli()` before any mysqli use.
- `database/install.php` (CLI) — inline guard: if `mysqli_connect` is missing, prints a clear
  error and exits 1.
- `app/Schema.php` — `Schema::installed()` returns `false` when mysqli is absent (defensive).
- `app/Database.php` — `Database::conn()` throws a descriptive `RuntimeException` when mysqli
  is missing.

### Verified
- With the **WinGet PHP (no mysqli)**: `/install.php` and `/` now return the clean
  "The PHP mysqli extension is not loaded" page (no fatal). Confirmed the body shows the
  XAMPP command + PHP 8.4.24 binary path.
- Regression with the **XAMPP PHP**: login + all modules return 200 (staff, students,
  promotion, finance, exams, timetable, notifications).

## Milestone 15: Superadmin role (full authorization, protected account)

Added a `superadmin` role as the main administrator with **complete authorization**; no other

- Added `superadmin` to the `role` ENUM on both `staff` and `users`.
- Seeded a dedicated superadmin: staff `SUPER0001` "Super Administrator" linked to user
  `superadmin` / `superadmin123`.

### Auth helpers (`app/helpers.php`)
- `is_superadmin()` — current user is superadmin.
- `is_admin()` — role is admin or superadmin.
- `require_role()` — **superadmin bypasses every role gate** (full authorization).
- `require_superadmin()` — superadmin-only guard.
- `is_protected_staff($staffId)` — is the staff record linked to a superadmin user.
- `can_manage_staff($staffId)` — allowed for superadmin, or any non-protected record.

  (flash + redirect) from viewing, editing, updating, or deleting the superadmin's record.
- `validate()`: only a superadmin may persist the `superadmin` role (forged payload rejected).

### Views
- `staff/index.php` — superadmin row shows a 🔒 Protected badge (no actions) to non-superadmins,
  👑 Superadmin badge, `superadmin` in the role filter, and `is_admin()` for delete gating.

- `staff/form.php` — `superadmin` role option shown only to superadmins.
- `classes/index.php`, `sessions/index.php` — delete buttons now use `is_admin()` so superadmin

### Live DB (XAMPP)
- Applied ENUM ALTERs and seeded `superadmin`, then verified via HTTP.

### Verified (end-to-end)
- Superadmin logs in; views/edits own record; full access to admin-only pages.

## Milestone 19: Fix "Add Staff with login" not creating the account

**Bug:** when adding a new staff member through the Staff form with "Create a login", the login
user was never saved, so the new user could not log in ("invalid username or password"). The
`users` row was never created because `StaffController::store()` collected the login fields
(`create_login`/`username`/`password`) but **never called `syncLogin()`** — only `update()` did.

**Fix:** added `$this->syncLogin((int)$id, $data);` in `store()` right after the staff insert and
salary-basis save, matching `update()`.

### Verified (end-to-end)
- Added a new staff "kkashif" (employee KKASHIF01) with a login via the web UI; the login user was
  created and `kkashif` / `123456` logged in successfully (Dashboard).
- The placeholder test record created during verification was removed afterwards so the user can
  re-add their staff member with correct details.
